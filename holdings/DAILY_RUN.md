## 每天做什么

1. 在两个仓库里分别 `git pull --ff-only`。
2. 打开主帖最后几页：https://www.tgb.cn/a/1ykAFNDujlw （最新楼在最后几页；只要作者 股海贼王 / userID 308803 的楼）。找到今天他发的国盛证券持仓截图（通常 15:00–15:30 北京时间）。今天没有就看上一交易日，并在记录里标明“未刷新”。
3. 从持仓图读取：总资产、浮动盈亏、当日参考盈亏、仓位、总市值；能看清的每一行（名称、代码、持仓、市值、盈亏、权重）。他常把中部个股打码，打码行不要猜名字。
4. 检查今天或本周是否新发了交割单（周五或周末常见；正文可能只写「本周交割单…」，也可能完全不提，要看图。手机「历史成交」长图，或带代码的电脑版表格。分时图不是交割单）。
   - 若有新交割单：把原图存进私有仓库 `archive/images/`，逐笔识别后追加到 `archive/trades/trades.csv`（列：trade_date,trade_time,stock_name,code,side,price,quantity,amount,fees,source_floor_url,image_hash,note）。用「价×量≈成交额」自检，长图拼接处去重。手续费若图上没有就留空。然后按基线 + 全部买卖重算净持股，更新公开仓库的 `holdings/reconstructed_positions.csv`，并用当天收盘价对一次账（重建个股市值应尽量等于截图「总市值 − 新标准券」）。方法细节见私有仓库 `archive/trades/README.md`。
5. 还原打码持仓：截图上能看清的，记为截图确认；台账显示仍有净持股、且与截图（打码行数、红蓝盈亏、市值）相符的，记为「由交割单推算」。上一张交割单之后的买卖尚未入账，不要猜测新买入的名字，只写还剩多少市值、大约几只。台账与截图对不上时，如实写分歧。
6. 和上一次 `holdings/` 记录对比，写出新开、清仓、仓位明显变化。只在文字里提到、或昨日有今日没有且台账也无法确认的，放入「可能已卖出 / 未确认」。
7. 写入公开仓库：
   - `holdings/YYYY-MM-DD.md`
   - 追加 `holdings/holdings.csv`（date,stock_name,code,shares,market_value,floating_pnl,weight,status,source_url；status 区分截图确认、由交割单推算、已清仓、未确认）
   - 更新 `holdings/reconstructed_positions.csv`（若台账有变）
   - 总资产是新数字时，追加 `data/equity_milestones.csv`
   把当天新抓到的原文、原图、OCR、交割单逐笔只提交到私有仓库。
8. 提交并推送两个仓库。提交说明写清楚日期和是否纳入了新交割单。

## 每日打码区推测（写入私有仓库 `archive/speculations/YYYY-MM-DD.md`，与确认数据严格隔离）

写完确认数据后，对打码区未知票做结构化推测。规则：**推测名字一律不得进入** `holdings.csv`、`reconstructed_positions.csv`、日报确认段落或任何公开仓库文件；推测文件页首必须标注「推测，未经交割单确认」。

流程：

1. **像素测量**行数与红蓝分布：深色模式截图按每行「饱和度>25 或 亮度<16」像素占比取信号，自相关定行距（同花顺持仓列表 199px），按行分红色(R>B+15)/蓝色(B>R+10)；用底部清仓行的已知红蓝序验证网格对齐。禁止用视觉模型目测行数。
2. **约束计算**：未知只数 = 打码行数 − 台账只数；未知市值 = 打码区个股市值 − 台账推算市值；未知成本 = 未知市值 −（截图浮盈 − 台账股浮盈）；红蓝配比按行数差分；T+1 差分（今日新买 = 今日行数 − 昨日行数 + 今日清仓数）；市值排序约束（持仓行按市值降序，未知票的行位置卡其市值上下限）。注意 0.5 成（198 万）是**单笔**不是单只，不能用来除出只数。
3. **候选筛选**：作者历史宇宙（trades.csv 出现过的全部票，含基线）+ 当日涨跌幅榜（新浪排序接口，jsonp kline 按 `[`…`]` 截取解析）+ 两日 K 线形态。红字坑筛「当日大涨（≥5%）、池内优先」；蓝字坑筛「昨涨（≥2%）∩ 今崩（≤−4%）」交集。旧票回锅给加权（他有 3 天内回锅的记录习惯）。**11-13 对账教训**：他约 2/3 的新买是从未做过的票（池外），且买入集中在**次日早盘**而非收盘形态可捕捉——名字层置信度上限低（结构层不受影响），输出时两层分开标注；交割单日前一日的推测只做结构，不做名字点名。
4. **自洽核验**（四关全过才输出）：市值排序位置、昨日红/今日蓝一致性、单笔规模、当日盈亏分解（含清仓票实际卖价≠收盘的修正）。不过关的坑降置信度或不点名。
5. **对账回写**：新截图清仓行、交割单揭晓名字时，逐坑核对前一交易日的推测文件，记录命中率与误差原因（行数测量/筛选条件/回锅先验哪一环错），把教训回写本节。

## 每日运行输出的固定格式（必须遵守）

运行结束的输出必须以两张表收尾，缺一不可：

1. **确定持仓表**：截图确认 + 交割单/台账确认的每一项（名称、代码、持股、成本、现价、市值、权重、红蓝、证据来源），以及新标准券。
2. **推测持仓表**：打码区未解行/未知名（市值、红蓝、结构约束、候选名字与置信度）。**若推测涉及新股**：先拉当周新股上市名单（新浪 `node=new_stock`），逐只核对「收盘价 × 整手股数 = 该行市值」且红蓝时序相符，比中即写名字并注明推断依据；比不中就写「非本周新股」并给出普通票候选。
3. 附现金流量残差（卖出回款 + 逆回购到期 − 再借出 − 可见买入 vs 现金变动）：大额无法解释的流出优先怀疑**新股中签缴款**（不进持仓页、不进历史成交、上市后才现身），并列入次日跟踪项。
